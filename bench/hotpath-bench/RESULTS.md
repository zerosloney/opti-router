- 日期：2026-09-11；环境：Windows 开发机（12 核，workstation GC），.NET 8.0.27，本机 MariaDB
- 工具：`reports/hotpath-bench`（零依赖 console harness，`OPTIROUTER_MARIADB_TEST` 提供库连接时含 DB 阶段）
- 方法：每组配置预热 300 次；单线程 2000 次采延迟（Stopwatch 时间戳）与分配量（`GC.GetAllocatedBytesForCurrentThread` 差值/操作）；吞吐为固定窗口（2s）内 `Parallel` 计数
- **口径声明：单机开发环境测量，用于量级决策与重构触发阈值，不冒充生产基准/SLA**

## 读数

1. **扫描成本是 O(N)，且有效/无效同价**：文件后端有效/无效明文完全一致（5000 keys 均 ~730µs）——常量时间全扫描的安全意图按设计工作，**不能**为速度改成提前退出而不做时序侧信道审查（审查报告同款警告，实测确认其真实性）。每 key 边际成本 ≈ 145ns + 56B 分配。
2. **并发 32 ≈ 并发 1**：全局锁串行化准入，无锁自旋/护航病态，但并行度对吞吐零贡献。
3. **DB 模式吞吐天花板 ≈ 1,400–2,000 ops/s，与 key 数无关**：瓶颈是全局锁内的 TryAdmit 往返（本机 RTT ~650µs），不是扫描。锁内 RTT 即单实例全局准入的序列化上限。
4. **DB 慢即全局准入线性变慢**：锁内 RTT 翻倍 → 全局准入吞吐减半；DB p95 达 5ms 时上限跌至 ~200 ops/s。

## 重构触发阈值（达到任一即启动对应改造）

| 阈值 | 触发的改造 | 预期收益 |
|---|---|---|
| DB p95 > 5ms（DB 变慢/远程化/多实例争抢） | TryAdmit 移出全局锁（后台/异步化或超时熔断） | 吞吐不再随 DB 延迟线性恶化；收益 ≈ RTT/扫描比 |
| 租户数 > 2,000（文件模式扫描 > 300µs/次） | 预解码不可变密钥快照（启动/变更时解码一次，授权路径零 hex 解码） | 高 key 数下延迟/分配降 ~5–20× |
| 需要多实例水平扩展准入 | TryAdmit 出锁 + 每租户分片锁 | 跨实例吞吐不再被单实例锁内 RTT 限制 |

## 决策

**当前规模（单实例、租户数远小于 1,000、本机 DB）不重构**：实测天花板 ~1,500 ops/s 远超单实例代理路由的实际租户准入需求；审查报告怀疑的"无效 key O(N) 扫描"与"全局锁内同步 DB"均已量化确认存在，但在此规模下代价可接受。改造点与收益排序已记录于上表，按阈值触发，不做预防性优化。
